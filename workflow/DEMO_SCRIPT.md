# VAULT-X — SIH Judge Demonstration Script

**Length:** 4 minutes 30 seconds (with ~30 s slack inside the 5-minute limit)
**Presenters:** two — **Presenter** (speaks, drives) and **Backup** (watches clock, handles fallback)
**Environment:** `demo` profile, `PROVIDER_MODE=snapshot`, seeded case data, AI enabled with deterministic fallback, SAHYOG mock.

---

## Ground rules for honesty (say these, don't hide them)

1. The screen shows a **SNAPSHOT DATA** banner. Say it once, early: *"This demo replays recorded chain data so it's reproducible; the same pipeline runs against live providers."* Only say the last clause if you have actually verified live mode works in your environment.
2. The **score** is labelled *uncalibrated*. Say: *"This is an evidence score, not a probability; calibration comes from ground-truth testing."*
3. **SAHYOG is a mock.** Say so on the final step.
4. Do not quote accuracy numbers unless the evaluation harness has produced them. If it has, cite the run ID.
5. Names of VASPs/addresses on screen come from the seeded dataset. If they are synthetic, say "seeded demo dataset".

## Backup/fallback plan

| Failure | Response |
|---|---|
| Graph slow/blank | Reload; if still failing, switch to pre-recorded video at the same beat and narrate |
| Verify fails unexpectedly | Do not hide it: "This is exactly what the integrity check is for" — then show the audit event; reseed after the demo |
| Workers not progressing | Switch to a pre-completed run (`r-0001`) — say "this is a completed run of the same pipeline" |
| LLM summary unavailable | Show deterministic summary; say AI is optional |
| Projector resolution issues | Use the Graph Explorer full-screen mode |
| Supervisor browser session expired | Show the approval screen in the recorded fallback |

## Anticipated judge questions and truthful answers

| Question | Answer |
|---|---|
| How accurate is it? | "We report only what our ground-truth harness measures. [If run: cite metrics and run ID, including false-attribution rate.] [If not: We haven't produced benchmark numbers yet; the harness and metrics are defined.]" |
| Where do exchange addresses come from? | "A provenance-tracked intelligence database seeded from documented public sources, with source tiers; the design accepts licensed feeds later. We don't have private exchange data." |
| Is it real-time? | "No — investigation-time analysis. Monitoring is on the roadmap." |
| Why not let an LLM do it? | "Attribution used in legal process must be reproducible and explainable. The LLM only translates queries and summarises verified evidence, and its output is validated against evidence IDs." |
| Is SAHYOG integrated? | "Not with the real system. We built a mock adapter and payload schema; a real integration needs the API specification and authorisation." |
| What about mixers? | "Mixer contamination caps the confidence band and is shown as a risk factor; the tool doesn't claim to defeat mixing." |
| What if the label is wrong? | "That's why contradictions and counterfactuals exist: leave-one-out shows which evidence is load-bearing." |
| Can this go beyond a prototype? | "Roadmap: technical MVP → agency pilot with SSO, at-rest encryption, WORM audit, licensed intel, security assessment." |

## Rehearsal protocol

1. Run the full script 3 times end-to-end on a clean environment; record each duration.
2. Rehearse the fallback for each failure in the table at least once.
3. Time-box: if any beat exceeds its budget by > 15 s in rehearsal, cut wording, not features.
4. Freeze the demo dataset and build 24 hours before; no last-minute changes.
